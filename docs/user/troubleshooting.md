# トラブルシューティング

症状別の確認事項をまとめる。原因を詳しく調べるときは、設定ディレクトリ内 `logs\` の当日ログを確認する (通常は `%APPDATA%\ClipRefiner\logs\`、ポータブル時は `data\logs\`。[ログ](configuration.md#ログ))。異常終了 (パニック) もログに記録される。不具合報告時は該当する日付のログファイルを添付する。

## 起動・表示

| 症状 | 確認事項 |
| :--- | :--- |
| 起動してもウィンドウが出ない | 常駐モードは通知領域のみで動作する。隠れているアイコンも確認する |
| 「ClipRefinerは既に実行されています。」と通知される | 常駐は同じ Windows ログオンセッションで 1 つしか起動できない。2 つ目の起動は通知して終了する。通知領域の既存のアイコンを確認する。ワンショットは常駐中も実行できる |
| 設定・セレクターが開かない | WebView2 Runtime 未導入の可能性。起動時通知や表示失敗時の導入ページ案内に従い Evergreen Runtime を入れ、アプリを再起動する。手動導入は [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) |
| アイドル時のメモリ使用量が増える | セレクターは既定 `Keep` で非表示後も `WebView` を保持する。[セレクター WebView の保持](configuration.md#セレクター-webview-の保持-selector_webview_retention) で `DisposeOnHide` / `DisposeAfterIdle` に切り替える |

## 加工・監視

| 症状 | 確認事項 |
| :--- | :--- |
| コピーしても加工されない | 新規インストールでは自動変換が無効である。トレイアイコンのツールチップが `変換モード: … (オフ)` なら、トレイ「変換モード → 自動変換を有効にする」で有効にするか、クイックセレクター (`Alt+Shift+S`) で手動変換する。有効なのに加工されない場合は、連続記録モード (連続記録モード中は自動変換が無効になる)・選択中のモード / 正規表現プリセットを、設定ウィンドウ「監視」タブで監視方式を確認する。パスワードマネージャー等が監視除外を指定したコピーは加工しない ([パスワードマネージャーの監視除外](security.md#パスワードマネージャーの監視除外)) |
| 「加工をスキップ」と通知される | 本文 2 MiB・パーサー 1 MiB・HTML の要素の入れ子 256 階層・正規表現 2 秒のいずれかの上限。入力を小さくするかパターンを見直す。[処理の制限](configuration.md#処理の制限) を参照 |
| 大きなテキストや画像を処理できない | [処理の制限](configuration.md#処理の制限) のサイズ・件数上限を確認する |
| Event 監視でも反応が遅い | クリップボードの更新通知を使えない環境では、短周期の監視に切り替わる。当日ログの警告を確認する |
| 通知が出ない | デスクトップ通知は既定で無効 (エラー通知だけ常に表示)。設定ウィンドウ「通知」タブか `Alt+Shift+N` でマスターを有効にし、種類別のトグルも確認する。Windows 側の通知設定や集中モードも確認する ([通知](configuration.md#通知-notification_settings)) |

## 設定ファイル

| 症状 | 確認事項 |
| :--- | :--- |
| 起動時に設定の解析エラーが出る | `config.toml.bak` を開いて通知・ログに示された TOML 構文を修正し、アプリ終了後に `config.toml` として戻す |
| 未対応の設定 version と出る | 移行手順が無いスキーマ番号でも既存項目は維持される。ディスク上の `version` は自動では書き換えない。[設定ファイルの場所](configuration.md#設定ファイルの場所) を参照 |
| 未知キーの警告が出る | [設定項目](configuration.md#設定項目) と照合し、タイプミスや廃止済みキーを削除する。既知の設定は引き続き適用される。旧キー (`notify_mode` / `paste_queue` など) は警告対象外 |
| 外部編集が反映されない | エディタで保存した直後に反映される。構文エラー通知と当日ログを確認する。設定ウィンドウ表示中はバナーでも知らせる。ディレクトリ監視が失敗している場合は約 2 秒の周期確認になる ([外部編集の自動再読み込み](configuration.md#外部編集の自動再読み込み)) |
| 設定や登録クリップを保存できない | 設定ディレクトリ (通常は `%APPDATA%\ClipRefiner`、ポータブル時は `data\`) の書き込み権限、空き容量、セキュリティソフトのブロックを確認する |
| ポータブルなのに `%APPDATA%` を見ている | 実行ファイルと同じフォルダにファイル名ちょうど `portable` があるか確認する。`CLIP_REFINER_CONFIG_DIR` が優先されていないかも確認する ([ポータブルモード](configuration.md#ポータブルモード)) |

## 登録クリップ

| 症状 | 確認事項 |
| :--- | :--- |
| 登録クリップが空になった / 一部が消えた | `registered-clips.dat` を読み込めなかった可能性がある。通知・当日ログを確認し、設定ディレクトリの `registered-clips.dat.bak` が残っているかを見る。鍵 (`registered-clips.key`) の欠落やファイルのロックなどの原因を取り除いてアプリを再起動すると、元ファイルから読み込める。空の状態で登録クリップを保存すると元ファイルを上書きするため、原因を取り除くまでは登録しない ([読み込みの異常時の挙動](configuration.md#読み込みの異常時の挙動)) |
| 「登録クリップの鍵を復号できない」と通知された | `registered-clips.key` を現在のユーザーの Windows DPAPI で復号できない。別ユーザーや別 PC へフォルダを移した場合や、Windows の再インストール後に起きる。登録クリップの読み込み・保存だけが行われず、設定は通常どおり保存される。鍵を作成した環境 (同じユーザー) で使うと復号できる。通知は 1 回の起動につき 1 回だけ表示する ([ポータブルモード](configuration.md#ポータブルモード)) |
| 「登録クリップの一覧が更新されたため、操作を中止しました」と出る | 設定ウィンドウの一覧が古いまま操作したため、別のクリップを変更しないよう中止した。一覧は最新になっているので、もう一度操作する ([登録クリップセレクター](usage.md#登録クリップセレクター-altshiftt)) |

## ホットキー

| 症状 | 確認事項 |
| :--- | :--- |
| ホットキーが反応しない | 他アプリとの重複を避け、設定ウィンドウ「ショートカット」で割り当てを変更する |
| 「〜を登録できません」と通知が出る | 通知に出たホットキーが他のアプリや OS と衝突している。そのキーだけが使えず、残りのホットキーは動作する。設定ウィンドウ「ショートカット」で別の割り当てへ変更する |
| ホットキーが既定値へ戻る | [対応するキー形式](configuration.md#ホットキー形式) か、他の割り当てと重複していないか確認する。設定ウィンドウから保存した場合は補正内容がフィードバック表示される |
| OCR が `Alt+Shift+O` のまま / 効かない | 既定は `Alt+Shift+G`。既存の `hotkeys.ocr` が残っている場合はそちらが優先されるため、設定ウィンドウ「ショートカット」または `config.toml` で変更する |

## 画面 OCR

| 症状 | 確認事項 |
| :--- | :--- |
| OCR の結果が空、または失敗の通知が出る | OCR エンジンの初期化に失敗している可能性がある。Windows の言語設定で、日本語など使う言語の OCR 機能 (言語パック) が入っているか確認する。選択範囲が小さすぎないかも確認する |
| `Alt+Shift+G` が反応しない | 他アプリと重複している可能性がある。設定ウィンドウ「ショートカット」で割り当てを変更する |

## 連続記録モード

| 症状 | 確認事項 |
| :--- | :--- |
| `Ctrl+V` してもキューが減らない | 貼り付け取り出しは `Alt+Shift+X` (`hotkeys.continuous_record_paste`)。通常の `Ctrl+V` は OS に任せ、キューを消費しない |

## ワンショット

| 症状 | 確認事項 |
| :--- | :--- |
| ワンショットが常駐に渡らない | 常駐が無ければそのまま実行する。常駐中に届かない場合は、二重加工を避けるため失敗する。待受の起動に失敗したときは通知される。[ワンショット IPC](security.md#ワンショット-ipc) を確認する |

## アプリの更新

| 症状 | 確認事項 |
| :--- | :--- |
| 更新確認が失敗する | ネットワークと当日ログを確認する |
| 更新の確認やダウンロードがエラーで終わる | 接続や応答が一定時間ない場合はタイムアウトとして扱う ([アプリの更新](usage.md#アプリの更新))。プロキシやファイアウォールを確認し、通信が安定してから再実行する。HTTPS の証明書は Windows の証明書ストアで検証するため、通信を検査するプロキシなどが使う独自の証明書は、Windows に信頼されていないと接続に失敗する |
| 更新を適用できない | ハッシュ・サイズ・署名・アセット名・CPU アーキテクチャのいずれかの検証に通らないアセットは適用しない ([アプリ更新の検証](security.md#アプリ更新の検証)) |
| 更新で認証エラーになる | キーを組み込んでいない古いビルドから、保護されたリリースへ更新しようとしている可能性がある。新しい版を手動で入れ直す |
| ポータブル更新後も古い版のまま | 自動で差し替えられなかったときは、展開先がエクスプローラーで開く。実行フォルダへ手動で上書きし、`portable` と `data\` を残したまま新しい `ClipRefiner.exe` を起動する |

## アンインストール

| 症状 | 確認事項 |
| :--- | :--- |
| アンインストールしても設定が残る | MSI のアンインストールで消えるのは、インストール先 (`%LOCALAPPDATA%\ClipRefiner`) とスタートメニューの項目、PATH への追加。設定・ログ・登録クリップ (`%APPDATA%\ClipRefiner`) は残る。完全に消すときは、そのフォルダを手動で削除する |
| アンインストール後も自動起動の項目が残る | アンインストールの前に、設定ウィンドウ「一般」タブでログイン時の自動起動をオフにしておく。残った場合は、Windows の「スタートアップ アプリ」から無効にする |
| ポータブル版を消したい | フォルダごと削除する。設定・ログ・登録クリップは、同じフォルダの `data\` にある |
| アンインストール・削除後にレジストリの項目が残る | 通知の表示名とアイコン用に、起動のたびに `HKCU\Software\Classes\AppUserModelId\com.y_hirata.clip-refiner` を書き込む (MSI・ポータブルとも)。アンインストールやフォルダの削除では消えない。不要なら、レジストリエディターでこのキーを削除する。残っても動作への影響はない |

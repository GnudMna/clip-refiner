# セキュリティ

クリップボードの内容・設定・アプリ更新をどう保護するか、またどこまでを保護の対象外とするかをまとめる。

## 信頼境界 (同一ユーザー前提)

ClipRefiner のローカル保護はいずれも **現在の Windows ユーザー** を境界とする。別ユーザーやネットワーク経由の到達は拒否するが、**同一ユーザーで動く他プロセス** からは OS のアクセス制御上到達しうる (マルウェア・別ツール・共有アカウント上の他アプリを含む)。

| 対象 | 守るもの | 同一ユーザーの他プロセス |
| :--- | :--- | :--- |
| **設定ディレクトリ** | 所有者専用 DACL (NTFS 等)。別ユーザーからの読み書きを拒否 | 同じユーザーなら読み取り・書き換えしうる |
| **登録クリップ鍵** | Windows DPAPI (現在ユーザースコープ) + 鍵ファイルの DACL | 同じユーザーなら DPAPI 解除とファイルアクセスが可能 |
| **ワンショット IPC** | 現在ユーザー専用 DACL + リモート拒否 | 同じユーザーならパイプへ接続し、加工指示を送りうる |
| **履歴・連続記録モード** | ディスク非永続・メモリ内暗号化 | プロセスメモリや UI 経由の到達は OS / ランタイム依存 (完全には防げない) |
| **設定 / セレクター WebView** | 埋め込み HTML の CSP (外部 script / connect 禁止、インライン script は同梱の固定スクリプトのみ許可) と `http(s)` / `file` 遷移・新規ウィンドウ・ダウンロード拒否 | 同一ユーザーならプロセス自体には到達しうる |

**運用上の目安:**

- 個人の専用アカウントで、信頼できるソフトウェアだけが動く環境を前提とする
- 共有アカウント、または信頼できない同一ユーザープロセスがある環境では、履歴をオフにする・登録クリップを使わない・使用後にクリア / 削除する
- ワンショットだけ使う場合は、常駐を終了してから実行すると IPC 委譲を避けられる
- クリップボード本体は OS 共有領域であり、本アプリの暗号化対象外である

設定ウィンドウの「クリップボード」タブにも短い注意を表示する。技術詳細は各対策の節と [ワンショット IPC](#ワンショット-ipc) を参照。

## 履歴・連続記録モードの保護

履歴・連続記録モードは機密情報を含む可能性があるため、**ディスクへ書き込まない**ことに加え、**メモリ上でも平文を常駐させない**よう多層的に保護している。機能の違いは [履歴](usage.md#履歴) / [連続記録モード](usage.md#連続記録モード) を参照。

| 対策 | 内容 |
| :--- | :--- |
| **ディスク非永続化** | 履歴・連続記録モードはファイル・DB へ書き込まず、プロセス実行中のメモリ上のみ。再起動で消える |
| **メモリ内暗号化** | 起動ごとに生成したセッション鍵 (32 バイト) で各エントリを ChaCha20-Poly1305 暗号化。エントリごとにランダムノンス |
| **平文の非保持** | 履歴の重複判定は、セッション鍵付き BLAKE3 ハッシュ (keyed hash) のみ。履歴・連続記録モードストア内に本文の平文は格納しない |
| **復号時のゼロ化** | 呼び出し・取り消しで復号した文字列は、使い終わった時点でゼロ化 |
| **終了時の破棄** | プロセス終了時に暗号鍵と暗号文バッファをクリア |
| **表示マスキング** | 通知・履歴メニュー・登録クリッププレビューで API キー・JWT 等を `[機密情報のため非表示]` に置換。**表示のみ**で、クリップボード本体や復元・コピー時の本文は書き換えない |

加工の取り消し用に保持する直近 1 件の加工前テキストも、同様にメモリ上のみ・ゼロ化付きで管理する。

## パスワードマネージャーの監視除外

パスワードマネージャー等は、コピーした内容を他アプリに監視させないためのクリップボードフォーマットを併せて載せる。監視時は本文を読む前にこれらを確認し、次のいずれかに該当するコピーは本文を読まずに無視する。

| フォーマット | 除外条件 |
| :--- | :--- |
| `ExcludeClipboardContentFromMonitorProcessing` | 存在する |
| `Clipboard Viewer Ignore` | 存在する |
| `CanIncludeInClipboardHistory` | 値が 0 (値を読めない場合も除外) |

除外したコピーは自動変換・履歴・連続記録モードのいずれにも入らない。`CanIncludeInClipboardHistory` = 0 も自動変換の対象外とするのは、加工結果を書き戻すと元の除外フォーマットが失われ、Windows のクリップボード履歴やクラウド同期へ載ってしまうためである。

ホットキー・トレイ・ワンショットによる手動加工と登録クリップへの登録、[テンプレート](usage.md#登録クリップのテンプレート)の `{clipboard}` による読み取りは、利用者の明示操作として除外指定に関わらず実行する。

手動加工の結果を書き戻すと元の除外フォーマットは失われるため、設定 `keep_clipboard_exclusion` (既定は有効。設定ウィンドウ「クリップボード」タブの「除外形式を付けてコピーする」) が有効なときは、書き込む内容に除外フォーマットを付ける。付けたコピーは Windows のクリップボード履歴 (Win+V)・クラウド同期・本アプリの監視に載らない。貼り付けは通常どおりできる。

| 書き込み | 除外フォーマットを付ける条件 |
| :--- | :--- |
| 手動加工・加工の取り消し・常駐へ委譲したワンショット | 書き込む直前のクリップボードに除外フォーマットがあったとき |
| 登録クリップのコピー | 常に付ける |

常駐なしで実行したワンショットは付けない。無効にすると、手動加工の結果も登録クリップのコピーも通常のコピーとして書き込み、Win+V 履歴やクラウド同期に載る。

## 表示マスキングの範囲

API キー・JWT・PEM 秘密鍵・資格情報行など機密らしい内容を `[機密情報のため非表示]` に自動置換する。マスキングは「画面に出す文言」だけを置換するため、次の点に注意する。

| 対象 | マスキング |
| :--- | :--- |
| 加工完了通知の内容 (`notify_result`) | する (表示のみ) |
| トレイ履歴・連続記録モードのメニューラベル | する (表示のみ) |
| 登録クリップの設定 UI / セレクタープレビュー | する (表示のみ) |
| クリップボード本体のテキスト | **しない** (加工対象のまま保持) |
| 履歴からの復元・登録クリップのコピー | **しない** (元の本文をクリップボードへ載せる) |

機密性の高い内容を扱ったあとは、履歴オフまたは「履歴をクリア」、登録クリップの削除を併用する。

## 登録クリップの保存とメモリ保護

登録クリップは履歴・連続記録モードと異なりディスクへ永続化するが、**ディスク上もメモリ上も本文平文を常駐させない**。

| 対策 | 内容 |
| :--- | :--- |
| **ディスク暗号化** | 本文は `registered-clips.dat`、画像は `registered-images/` に ChaCha20-Poly1305 で保存。外側 blob も同鍵で一括暗号化し、ラベル等のメタデータも保護する |
| **エントリ単位の本文暗号文** | メモリ上でも本文は暗号文のまま保持する。旧形式 (平文) の登録クリップは、読み込み時に移行する |
| **復号時のゼロ化** | コピー時だけ復号し、使い終わった時点でゼロ化する |
| **表示用キャッシュ** | `label` / `preview` は登録時に作った表示用断片 (マスク済みまたは切り詰め) のみ。履歴メニューラベルと同水準で、フル本文ではない |
| **鍵保護** | `registered-clips.key` を Windows DPAPI (現在ユーザースコープ) で保護し、現在ユーザー専用 DACL を付与する |

設定ウィンドウ・セレクターのプレビューはキャッシュ済み `preview` を使い、一覧表示のたびに本文を復号しない (表示のみ。コピー時は元の本文を載せる)。

設定ウィンドウで登録クリップを[編集](usage.md#登録クリップの編集)するときだけは、利用者の操作で本文を復号して編集ダイアログへ渡す。マスキングはせず、ダイアログを閉じると入力欄の本文を消す。保存した本文は、登録時と同じく暗号化して保持する。

登録クリップをバックアップ・移行する場合は `registered-clips.dat`、`registered-clips.key`、`registered-images/` を一組として扱う。鍵は作成した Windows ユーザーの DPAPI で保護されるため、別ユーザーや別環境へファイルだけコピーしても復号できない。`registered-clips.key` を失うと保存済みデータは復元できない。

> **補足:** OS のメモリスワップや他プロセスからのメモリダンプなど、ランタイム環境に依存するリスクまでは完全には防げない。プロセス内には DPAPI 解除後の鍵キャッシュがあり、UI には短い `preview` / `label` が残る。機密性の高い内容は履歴をオフにするか、使用後に「履歴をクリア」・登録クリップの削除を併用することを推奨する。

## 画像のファイル貼り付け

`excel-to-image` と `base64-decode` (画像) は、画像をエクスプローラへ貼り付けられるよう、ビットマップに加えて PNG のファイルもクリップボードへ載せる ([画像のファイル貼り付け](modes.md#画像のファイル貼り付け))。

| 項目 | 内容 |
| :--- | :--- |
| **ディスクへの書き出し** | しない。貼り付け先から求められたときに、メモリ上の PNG を直接渡す。別の内容をコピーすると、渡す PNG も破棄する |
| **登録クリップの画像** | ビットマップだけをクリップボードへ載せる。自動変換が `excel-to-image` でも、コピーした画像を加工しない。履歴・連続記録モードは画像を扱わない |
| **以前の版が書き出したファイル** | 4.0 系までは、PNG を `%TEMP%\ClipRefiner\clipboard-images\` に暗号化せず書き出していた。残っているファイルは常駐の起動時に削除する |
| **到達しうる相手** | クリップボードを読める、同一ユーザーで動く他プロセス ([信頼境界](#信頼境界-同一ユーザー前提)) |

## 一時フォルダの作業ファイル

更新のダウンロードや WebView の初期化で、`%TEMP%` に作業用のフォルダ (`clip-refiner-update`、`ClipRefiner-*-WebView2*` 内の `pid-*`) を作ることがある。常駐の起動時に、作成から 1 日を過ぎたものを削除する。更新のフォルダには、実行中の更新プログラムの複製とダウンロードしたインストーラーまたは ZIP が含まれ、クリップボードの内容は含まれない。複製は更新の画面を閉じたとき、ダウンロードは更新が終わったときに削除する (途中でやめた場合のダウンロードは上記のとおり 1 日後)。

## ワンショット IPC

トレイ常駐中に `--mode` / `--pipeline` を実行すると、CLI は名前付きパイプで常駐プロセスへ加工を委譲する (常駐が無い場合はローカル実行。常駐中に接続できない場合は二重加工を避けるため失敗する)。待受スレッドの起動に失敗した場合はデスクトップ通知し、監視は継続する。パイプは次のように保護する。

| 対策 | 内容 |
| :--- | :--- |
| **リモート拒否** | ネットワーク経由の接続を拒否する |
| **現在ユーザー専用 DACL** | パイプ作成時に現在ユーザーへだけアクセスを付与し、他の Windows ユーザーや Everyone 既定 ACE からの接続を拒否する |
| **ログオンセッションごとのパイプ** | パイプ名にログオンセッション ID を含め、常駐の多重起動防止と同じくセッションごとに分ける。CLI は接続先パイプの作成元が同じセッションであることを確かめ、別セッションのプロセスが作成したパイプには要求を送らない |

常駐側は接続ごとに処理スレッドを分け、同時に 4 接続まで処理する。上限に達している間の新しい接続は、処理中の接続が終わるまで待たされる (CLI 側は短時間の再接続後に失敗する)。接続後 5 秒以内に要求 1 行を受け取り終えない接続は、応答せずに切断する。

脅威モデル (同一ユーザーの他プロセスは到達しうる) は [信頼境界 (同一ユーザー前提)](#信頼境界-同一ユーザー前提) を参照。信頼できない同一ユーザープロセスが動いている環境では、常駐を終了してからワンショットを使うか、加工対象のクリップボード内容に注意する。

## アプリ更新の検証

適用前に次の検証をすべて通過する必要がある。適用手順は [アプリの更新](usage.md#アプリの更新) を参照。

**完全性検証:** GitHub API が返す各アセットの `digest` (`sha256:<hex>`) を必須とし、ダウンロード後にサイズと SHA-256 が一致した場合のみ適用する。宣言サイズが 0 または絶対上限 (512 MiB) を超えるアセットは確認時点で拒否する。ダウンロード中に宣言サイズを超えた応答は途中で打ち切り、不完全なファイルは削除する。digest が無いリリースやハッシュ / サイズ不一致は更新対象外 (適用しない)。実行中のアプリと CPU アーキテクチャが一致しないアセットへはフォールバックしない。

**署名検証:** 各アセットには開発者の秘密鍵による minisign (Ed25519) 署名 (`<アセット名>.minisig`) が必要で、更新プログラムに埋め込まれた公開鍵で検証できた場合のみ適用する。署名には更新先のバージョンとアセット名も含まれ、一致しない場合 (古い版のアセットを新しい版として配られた場合など) も適用しない。配信経路や GitHub API の応答が改ざんされても、正規の秘密鍵が無ければ偽のアセットは適用されない。署名が無い・検証に失敗したアセットは削除する。署名の検証に対応する前の版 (1.0 系まで) からの更新は、その 1 回だけ署名なしで適用される。

**タグ・アセット名・起動先:** GitHub API が返す最新タグは、ダウンロード URL と作業フォルダ名に使うため、`v` + SemVer (`v1.4.2` など) の厳密な形だけを受け付ける。前後の空白・大文字の `V`・`v` なし・パス区切りを含むタグは、正規化せず更新確認で拒否する。アセット名は保存先のファイル名とダウンロード URL に使うため、ASCII 英数字と `.` `-` `_` だけからなる単一のファイル名 (先頭・末尾の `.`・Windows の予約デバイス名・200 バイト超を除く) に限る。パス区切りや `..` を含む名前は更新確認時と適用直前の両方で拒否する。MSI の適用ではシステムフォルダの `msiexec.exe` を絶対パスで起動し、実行ファイルと同じフォルダに置かれた同名ファイルを起動しない。

**アプリの終了と起動:** 更新プログラムは、起動元のアプリだけに終了を依頼する。指定されたプロセスが実行フォルダの `ClipRefiner.exe` でなければ、何も変更せずに中止する。依頼と起動完了の通知には、同じ利用者・同じログオンセッションからだけ開ける仕組みを使う。

**通信経路:** 更新の確認とダウンロードは HTTPS で行い、リダイレクト先も HTTPS に限る。HTTP へのリダイレクトは接続せずに失敗とする。

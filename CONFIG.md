## 設定ファイルの場所

設定ファイル (`config.toml`) は設定変更のたびに自動保存され、以下の場所に配置されます。MSI のインストール先 (`%LOCALAPPDATA%\ClipRefiner`) とは異なります。通常の保存は同じディレクトリの一時ファイルへ書き込んでから置き換えるため、書き込み途中の終了による破損を抑制します。保存に失敗した場合はデスクトップ通知で案内します。

解決の優先順位:

1. 環境変数 `CLIP_REFINER_CONFIG_DIR` (非空のとき。テスト / E2E / 明示指定向け)
2. [ポータブルモード](#ポータブルモード) (`<実行ファイルのフォルダ>\data`)
3. 既定の `%APPDATA%\ClipRefiner`

| 利用形態 | パス |
| :------- | :--- |
| **通常** (既定) | `%APPDATA%\ClipRefiner\config.toml` |
| **ポータブル** | `<実行ファイルのフォルダ>\data\config.toml` |

設定ディレクトリ内の主なファイル / フォルダ:

| パス                   | 内容                                          |
| :--------------------- | :-------------------------------------------- |
| `config.toml`          | メイン設定 (変換モード・ホットキー・通知など) |
| `config.toml.bak`      | 解析に失敗した `config.toml` の退避コピー      |
| `registered-clips.dat` | 登録クリップ本文 (ChaCha20-Poly1305 暗号化)   |
| `registered-clips.key` | 登録クリップ用鍵 (Windows DPAPI で保護)       |
| `registered-images/`   | 登録クリップ画像 (暗号化)                     |
| `settings-window.json` | 設定ウィンドウのサイズ・位置                  |
| `logs/`                | 日次ログ (`clip-refiner.log.YYYY-MM-DD`)      |

設定ファイルの解析に失敗した場合、壊れた元ファイルは `config.toml.bak` として退避され、デフォルト設定で起動します。`.bak` は正常だった前世代のバックアップではないため、そのまま復元せず構文を修正してください。起動時にデスクトップ通知 (常駐モード) または標準エラー出力 (ワンショット) で案内されます。

認識できないキー (タイプミスや廃止名・未サポート項目) がある場合も読み込み自体は継続し、既知の項目だけ適用します。起動時・再読み込み時にログへ記録し、デスクトップ通知 (常駐) または標準エラー出力 (ワンショット) でキー名を案内します。旧キー (`notify_mode` / `hotkeys.paste_queue` など) や serde の別名は警告対象外です。

TOML 形式のため `#` でコメントを書けます。初回保存時は各項目の説明コメントが付与され、以降の保存ではユーザーが追記したコメントを維持したまま値のみ更新されます。設定ディレクトリとログファイルは、可能な場合に現在ユーザー専用 DACL で保護されます (FAT / exFAT など ACL 非対応ボリュームではスキップし、警告のみ記録します)。

### ポータブルモード

実行ファイルと同じフォルダに、名前が `portable` のファイル (中身は空でよい) を置くと、設定・ログ・登録クリップを実行ファイル隣の `data\` へ保存します。フォルダごと USB メモリへコピーして持ち出せます。

```
ClipRefiner.exe
portable          ← このファイルがある
data\
  config.toml
  logs\
  registered-clips.dat
  ...
```

有効化手順:

1. `ClipRefiner.exe` と同じフォルダに空の `portable` ファイルを作成する
2. アプリを起動する (初回は `data\` が自動作成される)
3. 必要なら `%APPDATA%\ClipRefiner` から `config.toml` や登録クリップ関連ファイルを `data\` へコピーする

注意:

- `CLIP_REFINER_CONFIG_DIR` が設定されているときはポータブルマーカーより優先される
- MSI インストール先へ `portable` を置くと、そのインストールの設定も `data\` 側へ切り替わる
- 登録クリップの鍵は Windows DPAPI (現在ユーザー) で保護されるため、別ユーザーや別 PC へフォルダを移すと復号できない場合がある
- ログイン時の自動起動はレジストリに実行ファイルの絶対パスを書くため、USB を抜き差しする用途には向かない
- アプリ内の [更新](#アプリの更新) でポータブル ZIP を適用しても `data\` は保持される
- 起動ログに `ポータブルモード: 設定ディレクトリ = ...` と出る

### 外部編集の自動再読み込み

常駐中は監視ループが約 2 秒ごとに `config.toml` の更新時刻を確認し、外部エディタでの変更を自動再読み込みします (アプリ自身の保存直後は誤検知を避けるため約 2 秒間は抑制)。手動編集した場合は、通常 2 秒以内にホットキー・監視設定などへ反映されます。再読み込み時に TOML の解析に失敗した場合、起動時と異なりデフォルト設定へのフォールバックは行わず、通知でエラーを表示します。未知キーを含む場合は反映を継続しつつ、再読み込み通知に検出したキーを含めます。設定ウィンドウを開いているときは、外部更新をバナーで知らせます。

## 最小構成例

初回起動でコメント付きの完全な `config.toml` が生成されるため、通常はそれを設定ウィンドウまたはエディタで変更します。手動で新規作成する場合の最小構成は次のとおりです。

```toml
version = 2
mode = "UrlDecode"
interval_ms = 1000
```

`version` は設定スキーマ用であり、アプリのバージョン番号ではありません。手動で増減せず、現行値を維持してください。変換モードは PascalCase で指定します。たとえば URL デコード後に前後の空白を除去する場合:

```toml
version = 2
mode = "UrlDecode"
pipeline = ["UrlDecode", "Trim"]
interval_ms = 1000
monitor_mode = "Event"

[notification_settings]
enabled = true
notify_result = false
```

利用できるキーと既定値は次の [設定項目](#設定項目) を参照してください。

## 処理の制限

| 対象                                | 上限                                                               |
| :---------------------------------- | :----------------------------------------------------------------- |
| クリップボード本文                  | 2 MiB                                                              |
| JSON / YAML / Markdown パーサー入力 | 1 MiB                                                              |
| 正規表現パターン                    | 8 KiB                                                              |
| 正規表現マッチ実行時間              | 2 秒                                                               |
| 正規表現マッチ同時実行              | 2 本                                                               |
| 登録クリップ                        | 100 件 (ラベル 64 文字、テキスト 2 MiB、画像 PNG 16 MiB / 8192 px) |
| 登録クリップ暗号化ファイル          | 256 MiB                                                            |
| お気に入り変換モード                | 20 件                                                              |
| 加工パイプライン                    | 10 段                                                              |
| ポーリング間隔 (`interval_ms`)      | 100〜60000 ms                                                      |

上限を超える入力は処理されず、登録クリップの追加は拒否されます。正規表現マッチが 2 秒を超えた場合は加工を中断し、クリップボードの元テキストを維持します (設定 UI のプレビューでは無効パターンとして表示)。同時に走れる正規表現マッチは最大 2 本で、タイムアウト後は協調キャンセルによりスロットを解放します (単一の `find` 実行中はエンジン制約で打ち切れない場合があります)。通知・履歴メニュー・登録クリッププレビューでは、API キー・JWT・PEM 秘密鍵・資格情報行など機密らしい内容を `[機密情報のため非表示]` に自動置換します。マスキングは**表示置換のみ**で、クリップボード本体・履歴復元・登録クリップのコピー結果は書き換えません。

## 変換モード一覧

`--mode` に渡す値 (CLI 名) と、トレイメニュー・クイックセレクターでの表示。**全 42 モード**に対応。

> **設定ファイル:** CLI は kebab-case (`url-decode` など) だが、`config.toml` では PascalCase (`UrlDecode` など) を指定する。初回保存時に生成される `config.toml` を参照するとよい。

| カテゴリ        | モード名 (`--mode`)                                                                                | 説明                                                          |
| :-------------- | :------------------------------------------------------------------------------------------------- | :------------------------------------------------------------ |
| **URL 操作**    | `url-encode` / `url-decode`                                                                        | URL のエンコード・デコード                                    |
|                 | `remove-utm`                                                                                       | URL から `utm_*` 計測パラメータを削除                         |
| **パス操作**    | `extract-basename` / `extract-basename-quoted`                                                     | パスからファイル名のみを抽出 (引用符付きオプションあり)       |
|                 | `add-path-quotes` / `remove-path-quotes`                                                           | パスへの引用符 (`"`) の付与・削除                             |
|                 | `path-to-slash` / `path-to-backslash`                                                              | パス区切り文字をスラッシュ / バックスラッシュに変換           |
| **行操作**      | `sort-lines-asc` / `sort-lines-desc`                                                               | 行単位での昇順・降順ソート (CSV 対応)                         |
|                 | `remove-empty-lines`                                                                               | 空行を削除                                                    |
|                 | `remove-duplicate-lines`                                                                           | 重複行を削除                                                  |
| **トリム**      | `trim`                                                                                             | テキスト全体の前後の空白・改行を削除                          |
|                 | `trim-lines`                                                                                       | 行ごとに前後の空白を削除                                      |
| **エスケープ**  | `escape` / `unescape`                                                                              | バックスラッシュエスケープの付与・解除                        |
|                 | `regex-escape` / `regex-unescape`                                                                  | 正規表現メタ文字のエスケープ・解除                            |
| **正規表現**    | `regex-replace`                                                                                    | パターンに一致する部分を置換 (`[regex]` 設定を使用)           |
|                 | `regex-extract`                                                                                    | パターンに一致する部分を行単位で抽出                          |
|                 | `regex-delete`                                                                                     | パターンに一致する部分を削除                                  |
|                 | `regex-split`                                                                                      | パターンで分割し改行で結合                                    |
| **JSON 整形**   | `json-format`                                                                                      | JSON をインデント整形 (キー順序不定)                          |
|                 | `json-format-preserve-order`                                                                       | JSON をインデント整形 (キー順序保持)                          |
| **JSON へ変換** | `yaml-to-json`                                                                                     | YAML を JSON へ変換 (キー順序不定)                            |
|                 | `yaml-to-json-preserve-order`                                                                      | YAML を JSON へ変換 (キー順序保持)                            |
| **YAML へ変換** | `json-to-yaml`                                                                                     | JSON を YAML へ変換 (キー順序不定)                            |
|                 | `json-to-yaml-preserve-order`                                                                      | JSON を YAML へ変換 (キー順序保持)                            |
| **Markdown**    | `markdown-to-html`                                                                                 | Markdown を HTML へ変換                                       |
| **Excel**       | `excel-to-markdown`                                                                                | Excel コピーデータを Markdown テーブルへ変換                  |
|                 | `markdown-to-excel`                                                                                | Markdown 表を Excel (TSV) 形式へ変換                          |
|                 | `excel-to-image`                                                                                   | Excel コピーデータの見た目を画像としてクリップボードへ保存    |
| **日時変換**    | `timestamp-to-datetime` / `datetime-to-timestamp`                                                  | Unix タイムスタンプ ↔ 日時文字列の変換 (ローカルタイムゾーン) |
| **数値変換**    | `add-comma` / `remove-comma`                                                                       | 数値への 3 桁カンマ区切り付与・削除                           |
| **ケース変換**  | `to-camel-case` / `to-snake-case` / `to-pascal-case` / `to-kebab-case` / `to-screaming-snake-case` | 識別子のケース変換                                            |

正規表現モードは `[regex]` セクションでパターン・置換文字列・オプションを設定する。

## ホットキー形式

`Alt+Shift+S` のように、`+` 区切りで修飾キーとキーを指定します。

- **修飾キー**: `Alt`, `Shift`, `Ctrl` (`Control` 可), `Meta` (`Super` / `Win` 可)
- **キー**: `A`〜`Z`, `0`〜`9`, `F1`〜`F12`, `Backspace`

不正な値や重複は読み込み時・設定 UI 保存時にデフォルトへ置き換えられます (お気に入りスロットの空文字は意図的な無効化として維持)。設定ウィンドウの「ショートカット」タブから保存した場合は、補正した割り当て名を適用フィードバックで表示します。

**既定値の変更と既存設定:**

| 項目 | 現行の既定 | 備考 |
| :--- | :--------- | :--- |
| `hotkeys.ocr` | `Alt+Shift+G` | 旧既定は `Alt+Shift+O`。`config.toml` に保存済みの値がある場合はそちらを維持する (キー欠落時のみ新既定を適用) |
| `hotkeys.continuous_record_paste` | `Alt+Shift+X` | 旧キー名 `paste_queue` は別名として読み込む。保存時は `continuous_record_paste` のみ出力する。連続記録の貼り付けは `Ctrl+V` 捕捉ではなくこのホットキー |

## 通知 (`notification_settings`)

デスクトップ通知は **マスター** (`notification_settings.enabled`) と **種類別トグル** で制御する。起動失敗・設定読み込み失敗・クリップボード初期化失敗などの **エラー通知はマスター OFF でも常に表示** する。

| 操作                       | 動作                                                                  |
| :------------------------- | :-------------------------------------------------------------------- |
| トレイ「通知」サブメニュー | マスター ON/OFF と種類別トグルの切替                                  |
| 設定ウィンドウ「通知」タブ | マスターと個別項目を GUI で編集 (マスター OFF 時も個別設定は変更可能) |
| `Alt+Shift+N`              | マスター ON/OFF のみ切替 (`hotkeys.notification`)                     |

種類別トグルと対象操作:

| キー                       | 既定    | 対象                                                          |
| :------------------------- | :------ | :------------------------------------------------------------ |
| `notify_process`           | `true`  | 監視モードでの加工完了                                        |
| `notify_pause`             | `true`  | 一時停止・再開                                                |
| `notify_history_restore`   | `true`  | 履歴からの復元                                                |
| `notify_ocr`               | `true`  | 画面 OCR 完了                                                 |
| `notify_registered_clip`   | `true`  | 登録クリップのコピー・登録                                    |
| `notify_favorites`         | `true`  | お気に入り変換の切替                                          |
| `notify_continuous_record` | `true`  | 連続記録の有効化・取り出しなど                                |
| `notify_result`            | `false` | 上記通知本文にクリップボード内容を含めるか (マスターとは独立) |

`notify_result` が `true` のときも、機密らしい内容は `[機密情報のため非表示]` にマスクする (通知本文の表示のみ。クリップボード本体は対象外)。加工パイプライン適用時の加工完了通知は、連鎖したモード名を連結して表示する ([加工パイプライン](#加工パイプライン-pipeline) 参照)。

**設定例:**

```toml
[notification_settings]
enabled = true
notify_process = true
notify_pause = false
notify_history_restore = true
notify_ocr = true
notify_registered_clip = true
notify_favorites = true
notify_continuous_record = true
notify_result = false
```

**旧設定からの移行:** v0.12.1 以前の `notify_mode` / `notify_actions` は読み込み時に新項目へ自動移行し、次回保存時に TOML から除去される。変更経緯は [CHANGELOG.md](CHANGELOG.md) の v0.12.2 を参照。

| 旧キー                                            | 移行先                                                                                                                          |
| :------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------ |
| `notify_mode = false` かつ `notify_result` 未指定 | `notify_process = false`                                                                                                        |
| `notify_actions = false`                          | `notify_history_restore` / `notify_ocr` / `notify_registered_clip` / `notify_favorites` / `notify_continuous_record` を `false` |

| **クリップボード監視を再開** | ワーカー初期化失敗などで監視が停止したときに手動復旧 (通常は無効)                                                                                                                  |
| **一時停止 / 終了**          | 監視の一時停止・再開、アプリ終了                                                                                                                                                   |

### クイックセレクター (`Alt+Shift+S`)

- **検索:** モード名・カテゴリ・CLI 名の部分一致 (ハイライト表示)
- **お気に入り:** 星印または `Ctrl+D` で登録・解除。`Ctrl+Shift+↑/↓` で並び替え
- **キー:** `↑/↓` 移動、`Enter` 決定、`Esc` クリアまたは閉じる
- **WebView 保持:** [セレクター WebView の保持](#セレクター-webview-の保持-selector_webview_retention) を参照

### 登録クリップセレクター (`Alt+Shift+T`)

- **登録:** トレイ「登録クリップ → クリップボードを登録」、またはセレクター内 `Ctrl+Enter` (画像優先)
- **上限:** 最大 100 件、ラベル 64 文字、テキスト 2 MiB、画像 PNG 16 MiB / 8192 px
- **キー:** `Enter` でコピー、`Del` で削除、`Esc` クリアまたは閉じる
- **WebView 保持:** [セレクター WebView の保持](#セレクター-webview-の保持-selector_webview_retention) を参照

登録クリップは `registered-clips.dat` (暗号化) と `registered-images/` に保存される (`config.toml` には含まれない)。

### 連続記録 (`Alt+Shift+C`)

- **有効化:** トレイ「連続記録 → 連続記録を有効にする」、または `Alt+Shift+C`
- **記録:** 監視時にコピーした元テキストを加工せずキュー末尾へ追加 (有効化時点のクリップボード内容は記録せず、以降のコピーから積む)
- **自動加工停止:** 有効中はコピー監視による自動加工を行わない。トレイの「変換モード」メニューは無効化され、連続記録サブメニュー名は「連続記録 (自動加工停止)」、ツールチップは「ClipRefiner (連続記録中・自動加工停止)」と表示される
- **取り出し:** `Alt+Shift+X` でキュー先頭をクリップボードへ載せてから貼り付け、またはトレイメニューから項目を選択して取り出し (除去)
- **取り消し:** トレイ「連続記録 → 直近の記録を取り消す」、または `Alt+Shift+Backspace` でキュー末尾 (直近コピー) を 1 件削除。クリップボード本体は変更しない
- **クリア:** トレイ「連続記録 → 記録をクリア」
- **上限:** 最大 `continuous_record_limit` 件 (1〜100、デフォルト 10)。超過時は先頭から破棄。同一内容の再コピーでも重複排除せず積む
- **手動加工:** お気に入りホットキーやクイックセレクターなど、明示的な手動加工は従来どおり動作する

### お気に入り変換モード

- **登録:** トレイ「変換モード → お気に入り」またはクイックセレクター `Ctrl+D`
- **上限:** 最大 20 件 (`favorite_modes` に永続化)
- **ホットキー:** 登録順に `Alt+Shift+1`〜`Alt+Shift+9` / `Alt+Shift+F1`〜`Alt+Shift+F11`。`hotkeys.favorite_mode_slots` でカスタマイズ (空文字で無効)

```toml
favorite_modes = ["UrlDecode", "Trim", "JsonFormat"]

[hotkeys]
favorite_mode_slots = ["", "Alt+Ctrl+J"]  # 2 件目のみカスタム、1 件目は無効
```

### 加工の取り消し (`Alt+Shift+Z`)

監視モード常駐時、加工成功直後の直近 1 件のみ取り消し可能。ワンショット (`--mode`) では利用不可。新しい加工が成功すると対象は上書きされる。

## 設定ウィンドウ

トレイ「設定を開く」で WebView ベースの設定ウィンドウを表示する。表示には [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) が必要。未導入の場合は起動時にデスクトップ通知で案内し、設定 / セレクターの表示失敗時は導入ページを既定ブラウザで開く (クリップボード監視・ホットキー・ワンショットは Runtime なしでも利用できる)。変更は約 200 ms の debounce 後に自動で `config.toml` へ保存され、トレイメニュー・監視ループへ即時反映される。ウィンドウを閉じる直前に保留中の変更は自動送信される (タイトルバーの閉じるボタン / ヘッダーの閉じる / `Esc` のいずれでも同様)。適用に失敗した場合はウィンドウ内にエラーを表示し、ウィンドウ非表示後もデスクトップ通知で伝える。ホットキーの不正・重複を補正して保存した場合は、どの割り当てを直したかを成功フィードバックで表示する。サイズと位置は設定ディレクトリ内の `settings-window.json` に保存される。

サイドバーは WAI-ARIA の `tablist` / `tab` / `tabpanel` パターンに準拠する。フォーカスがタブ上にあるときは上下・左右矢印と Home / End でタブを移動できる。

ヘッダーの **config.toml** ボタン、または「ショートカット」タブから設定ファイルを既定エディタで開ける。ホットキー割り当ては設定ウィンドウの「ショートカット」タブで編集できる (`config.toml` の `[hotkeys]` でも同様に編集可能)。

| タブ               | 内容                                                                                                                                                        |
| :----------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **一般**           | ログイン時の自動起動・セレクター WebView 保持方針・バージョン表示・[更新確認 / 適用](#アプリの更新)                                                      |
| **お気に入り**     | お気に入り変換モードの追加・並び替え・削除 (最大 20 件)                                                                                                     |
| **正規表現**       | `[regex]` のパターン・置換文字列・オプション。Rust 正規表現エンジンによるライブプレビュー付き                                                               |
| **履歴・連続記録** | 有効化・保持件数・クリア。連続記録 ON 時はバナーで自動加工停止を表示                                                                                        |
| **登録クリップ**   | 一覧表示・コピー・削除・クリップボードからの新規登録                                                                                                        |
| **監視**           | 一時停止、監視方式・周期 (100〜60000 ms の数値入力)、デフォルトモード、加工パイプラインの追加・並び替え・削除。連続記録 ON 時は加工設定セクションを無効表示 |
| **通知**           | マスター ON/OFF、加工完了・一時停止・履歴復元・OCR・登録クリップ・お気に入り・連続記録の個別トグル、クリップボード内容表示 (`notify_result`)                |
| **ショートカット** | グローバルホットキーの編集 (固定割り当て + お気に入りスロット。空欄でお気に入りスロットを無効化)                                                            |

**正規表現タブ:** パターン入力中はクライアント側でバイト長を検証し、構文チェックと `regex-replace` の置換プレビューはバックエンド (本番と同じ Rust エンジン) で実行する。プレビュー用サンプル文字列は UI で任意に編集できる (初期値は `Hello world 123`。設定には保存しない)。コンパイルできないパターンは保存されない。履歴・連続記録・登録クリップの削除は確認ダイアログを表示する。

**監視タブのデフォルトモード:** `pipeline` が空のときは従来どおり監視で適用するモードを切り替える。`pipeline` が設定済みのときは `mode` のみ更新し、パイプライン自体は維持する (監視で適用されるのは `pipeline` の連鎖)。パイプラインをクリアすると、保存済みの `mode` が再び適用される。

## 画面 OCR

`Alt+Shift+G` で全画面オーバーレイを表示し、ドラッグで範囲選択。確定後にキャプチャと OCR を実行し、結果をクリップボードへ書き込む。`Esc` または再度ホットキーでキャンセル。

OCR エンジンは `Windows.Media.Ocr` (日本語言語パック優先)。範囲選択は Win32 ネイティブオーバーレイ。キャプチャと認識は同時に 1 本だけ実行し、新しい範囲選択が始まると進行中ジョブの結果書き込み・通知は破棄する (エンジン自体の強制中断はできない)。

- **小さい選択範囲:** 短辺が小さい画像は自動拡大してから OCR
- **日本語の空白:** OCR が挿入する不要スペースを除去 (英単語間は維持)

---

## 加工パイプライン (`pipeline`)

`pipeline` に複数の変換モードを指定すると、クリップボード監視時に左から順に連鎖適用されます。空の場合は従来どおり `mode` のみが適用されます。`pipeline` が非空のときに `mode` だけを変更しても監視で適用される連鎖は変わりません (次に `pipeline` をクリアしたときのデフォルトとして `mode` が使われます)。トレイメニューからモードを選択すると `pipeline` はクリアされ、単一モードへ切り替わります。[設定ウィンドウ](#設定ウィンドウ) の監視タブでも同様にパイプラインとデフォルトモードを編集できます。

```toml
mode = "UrlDecode"
pipeline = ["UrlDecode", "Trim", "JsonFormat"]
```

- **最大段数**: 10 段まで
- **画像出力**: `ExcelToImage` はパイプライン末尾へ自動移動
- **通知**: 連鎖適用時は `URLデコード → 全体をトリム → JSON整形` のようにモード名を連結して表示

ワンショット実行時は CLI の `--pipeline` でも同様に連鎖指定できます (`--mode` より優先)。トレイ常駐中は常駐プロセスへ IPC 委譲し、監視の再加工を避けます。常駐が無い場合のみローカルで直接加工します。例:

```powershell
.\ClipRefiner.exe --pipeline url-decode trim json-format
```

## 監視方式 (`monitor_mode`)

| 方式      | 説明                                                                                                |
| :-------- | :-------------------------------------------------------------------------------------------------- |
| `Event`   | (既定) Windows の `AddClipboardFormatListener` で変更通知を受け取り、変更時のみ本文を読む。アイドル時はシーケンストークンの周期 peek を行わないため、ポーリングより低遅延かつ低 CPU 負荷。リスナ初期化に失敗した場合のみシーケンストークンの短周期監視へフォールバックする |
| `Polling` | 一定間隔 (`interval_ms`) でクリップボードの内容を読み取り、変更を検知する方式 |

どちらの方式でも、クリップボード本文の読み書きは専用ワーカーに集約する。変更検知 (シーケンストークン / OS リスナ) と Excel 向け画像取得は別経路とし、同じ操作でクリップボードを二重に開かない。実装の詳細は [DEVELOPMENT.md のスレッドモデル](DEVELOPMENT.md#スレッドモデル) を参照。

## セレクター WebView の保持 (`selector_webview_retention`)

クイックセレクター / 登録クリップセレクターの `WebView` を、非表示後どう扱うか。再表示の速さ (保持) とアイドル時のメモリ (破棄) のトレードオフ。設定ウィンドウと画面 OCR オーバーレイは従来どおり非表示時に破棄する (この設定の対象外)。

| 値                 | 動作 |
| :----------------- | :--- |
| `Keep` (既定)      | 非表示後も `WebView` を保持し、再表示を高速化する (アイドル時の RSS は増える) |
| `DisposeOnHide`    | 非表示時に `WebView` を破棄する |
| `DisposeAfterIdle` | 非表示から `selector_webview_idle_minutes` 分 (1〜1440、既定 5) 経過後に破棄する |

設定ウィンドウ「一般」タブからも変更できる。`DisposeAfterIdle` のときだけアイドル分数入力が有効になる。

```toml
# 再表示を優先 (既定)
selector_webview_retention = "Keep"

# メモリを優先する場合の例
# selector_webview_retention = "DisposeAfterIdle"
# selector_webview_idle_minutes = 5
```

## 連続記録

履歴とは独立した FIFO キュー。トレイ「連続記録 → 連続記録を有効にする」または `Alt+Shift+C` で有効化 (`continuous_record_enabled`、デフォルト無効)。監視時は加工を行わずコピーした元テキストを専用キューへ末尾追加する。有効化時点で既にあるクリップボード内容は記録せず、以降のコピーから積む。有効中はコピー監視による自動加工が停止し、トレイの変換モードメニューは無効化される。最大 `continuous_record_limit` 件 (1〜100、デフォルト 10) を保持し、上限超過時は先頭から破棄する。同一内容の再コピーでも重複排除せず積む。

| 操作                                   | 動作                                                                                                                                   |
| :------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| コピー (監視)                          | 元テキストをキュー末尾へ追加                                                                                                           |
| `Alt+Shift+X` 貼り付け                | キュー先頭をクリップボードへ載せてから通常の貼り付けを実行 (キューが空、または連続記録 OFF のときは現在のクリップボード内容を貼り付け) |
| トレイメニュー項目選択                 | 指定位置のエントリをクリップボードへ取り出し (除去)                                                                                    |
| 直近の取り消し (`Alt+Shift+Backspace`) | キュー末尾 (直近コピー) を 1 件削除。クリップボードは変更しない                                                                        |
| 有効化直後                             | 既存のクリップボード内容は記録せず、以降のコピーからキューへ積む                                                                       |

```toml
continuous_record_enabled = true
continuous_record_limit = 10

[hotkeys]
continuous_record = "Alt+Shift+C"
continuous_record_undo = "Alt+Shift+Backspace"
continuous_record_paste = "Alt+Shift+X"
```

ホットキーやメニューからの手動加工は従来どおり動作する。トレイメニューとホットキーの操作は [UI 操作](#ui-操作) を参照。

## クリップボード履歴のセキュリティ

履歴はトレイ「履歴 → 履歴機能を有効にする」で有効化 (`history_enabled`、デフォルト無効)。最大 `history_limit` 件 (1〜100、デフォルト 10) を保持し、同一内容は最新位置へ移動して重複しない。

連続記録も履歴と同様に**ディスクへ書き込まず**、メモリ上で ChaCha20-Poly1305 暗号化して保持する (プロセス終了で消える)。機能の違いは [連続記録](#連続記録) を参照。

履歴は機密情報を含む可能性があるため、**ディスクへ書き込まない**ことに加え、**メモリ上でも平文を常駐させない**よう多層的に保護している。

| 対策                 | 内容                                                                                                             |
| :------------------- | :--------------------------------------------------------------------------------------------------------------- |
| **ディスク非永続化** | 履歴・連続記録はファイル・DB へ書き込まず、プロセス実行中のメモリ上のみ。再起動で消える                          |
| **メモリ内暗号化**   | 起動ごとに生成したセッション鍵 (32 バイト) で各エントリを ChaCha20-Poly1305 暗号化。エントリごとにランダムノンス |
| **平文の非保持**     | 履歴の重複判定は BLAKE3 ハッシュのみ。履歴・連続記録ストア内に本文の平文は格納しない                             |
| **復号時のゼロ化**   | 呼び出し・取り消しで復号した文字列は `SecretString` で保持し、スコープ終了時にゼロ化                             |
| **終了時の破棄**     | プロセス終了時に暗号鍵と暗号文バッファをクリア                                                                   |
| **表示マスキング**   | 通知・履歴メニュー・登録クリッププレビューで API キー・JWT 等を `[機密情報のため非表示]` に置換。**表示のみ**で、クリップボード本体や復元・コピー時の本文は書き換えない |

加工の取り消し用に保持する直近 1 件の加工前テキストも、同様にメモリ上のみ・ゼロ化付きで管理する。

#### 表示マスキングの範囲

マスキングは「画面に出す文言」だけを置換する。次の点に注意する。

| 対象 | マスキング |
| :--- | :--- |
| 加工完了通知の内容 (`notify_result`) | する (表示のみ) |
| トレイ履歴・連続記録のメニューラベル | する (表示のみ) |
| 登録クリップの設定 UI / セレクタープレビュー | する (表示のみ) |
| クリップボード本体のテキスト | **しない** (加工対象のまま保持) |
| 履歴からの復元・登録クリップのコピー | **しない** (元の本文をクリップボードへ載せる) |

機密性の高い内容を扱ったあとは、履歴オフまたは「履歴をクリア」、登録クリップの削除を併用する。

### 登録クリップの保存とメモリ保護

登録クリップは履歴・連続記録と異なりディスクへ永続化するが、**ディスク上もメモリ上も本文平文を常駐させない**。

| 対策 | 内容 |
| :--- | :--- |
| **ディスク暗号化** | 本文は `registered-clips.dat`、画像は `registered-images/` に ChaCha20-Poly1305 で保存。外側 blob も同鍵で一括暗号化し、ラベル等のメタデータも保護する |
| **エントリ単位の本文暗号文** | ランタイムの `AppConfig.clips` には AEAD 暗号文 (`text_ciphertext`) のみを保持する。旧形式 (平文 `text` フィールド) は読み込み時に移行する |
| **復号時のゼロ化** | コピー時だけ `SecretString` へ復号し、スコープ終了時にゼロ化する |
| **表示用キャッシュ** | `label` / `preview` は登録時に作った表示用断片 (マスク済みまたは切り詰め) のみ。履歴メニューラベルと同水準で、フル本文ではない |
| **鍵保護** | `registered-clips.key` を Windows DPAPI (現在ユーザースコープ) で保護し、現在ユーザー専用 DACL を付与する |

設定ウィンドウ・セレクターのプレビューはキャッシュ済み `preview` を使い、一覧表示のたびに本文を復号しない (表示のみ。コピー時は元の本文を載せる)。

登録クリップをバックアップ・移行する場合は `registered-clips.dat`、`registered-clips.key`、`registered-images/` を一組として扱う。鍵は作成した Windows ユーザーの DPAPI で保護されるため、別ユーザーや別環境へファイルだけコピーしても復号できない。`registered-clips.key` を失うと保存済みデータは復元できない。

> **補足:** OS のメモリスワップや他プロセスからのメモリダンプなど、ランタイム環境に依存するリスクまでは完全には防げない。プロセス内には DPAPI 解除後の鍵キャッシュがあり、UI には短い `preview` / `label` が残る。機密性の高い内容は履歴をオフにするか、使用後に「履歴をクリア」・登録クリップの削除を併用することを推奨する。

### 信頼境界 (同一ユーザー前提)

ClipRefiner のローカル保護はいずれも **現在の Windows ユーザー** を境界とする。別ユーザーやネットワーク経由の到達は拒否するが、**同一ユーザーで動く他プロセス** からは OS のアクセス制御上到達しうる (マルウェア・別ツール・共有アカウント上の他アプリを含む)。

| 対象 | 守るもの | 同一ユーザーの他プロセス |
| :--- | :--- | :--- |
| **設定ディレクトリ** | 所有者専用 DACL (NTFS 等)。別ユーザーからの読み書きを拒否 | 同じユーザーなら読み取り・書き換えしうる |
| **登録クリップ鍵** | Windows DPAPI (現在ユーザースコープ) + 鍵ファイルの DACL | 同じユーザーなら DPAPI 解除とファイルアクセスが可能 |
| **ワンショット IPC** | 現在ユーザー専用 DACL + リモート拒否 | 同じユーザーならパイプへ接続し、加工指示を送りうる |
| **履歴・連続記録** | ディスク非永続・メモリ内暗号化 | プロセスメモリや UI 経由の到達は OS / ランタイム依存 (完全には防げない) |

**運用上の目安:**

- 個人の専用アカウントで、信頼できるソフトウェアだけが動く環境を前提とする
- 共有アカウント、または信頼できない同一ユーザープロセスがある環境では、履歴をオフにする・登録クリップを使わない・使用後にクリア / 削除する
- ワンショットだけ使う場合は、常駐を終了してから実行すると IPC 委譲を避けられる
- クリップボード本体は OS 共有領域であり、本アプリの暗号化対象外である

設定ウィンドウの「履歴・連続記録」「登録クリップ」タブにも短い注意を表示する。技術詳細は各対策の節と [ワンショット IPC](#ワンショット-ipc) を参照。

### ワンショット IPC

トレイ常駐中に `--mode` / `--pipeline` を実行すると、CLI は名前付きパイプで常駐プロセスへ加工を委譲する (常駐が無い場合はローカル実行)。パイプは次のように保護する。

| 対策 | 内容 |
| :--- | :--- |
| **リモート拒否** | `PIPE_REJECT_REMOTE_CLIENTS` によりネットワーク経由の接続を拒否する |
| **現在ユーザー専用 DACL** | パイプ作成時に現在ユーザーへだけアクセスを付与し、他の Windows ユーザーや Everyone 既定 ACE からの接続を拒否する |

脅威モデル (同一ユーザーの他プロセスは到達しうる) は [信頼境界 (同一ユーザー前提)](#信頼境界-同一ユーザー前提) を参照。信頼できない同一ユーザープロセスが動いている環境では、常駐を終了してからワンショットを使うか、加工対象のクリップボード内容に注意する。

## アプリの更新

トレイ「更新を確認…」、または設定ウィンドウ「一般」タブの「更新を確認」から最新リリースを調べる。起動時の自動チェックは行わない。配信は [gh-release-bridge](https://gh-release-bridge.gnudlemna-4656.workers.dev/GnudMna/clip-refiner) 経由で、GitHub プライベート Release の MSI / ポータブル ZIP のみを対象とする。

| 利用形態 | 適用手順 |
| :--- | :--- |
| **インストール版 (MSI)** | 新しい版があれば「ダウンロードして適用」で MSI を取得し `msiexec` を起動したあとアプリを終了する |
| **ポータブル** | ZIP を一時フォルダへ展開し、差し替えヘルパー (`ClipRefiner.exe --apply-portable-update`) が旧プロセス終了を待って実行フォルダへ上書きコピーしたあと新しい版を起動する。`data\` は保持する。ヘルパー起動に失敗した場合のみ展開先をエクスプローラーで開き、手動差し替えを案内する |

**完全性検証:** version API の各アセットに付与された `digest` (`sha256:<hex>`、GitHub Release Asset の digest) を必須とし、ダウンロード後にサイズと SHA-256 が一致した場合のみ適用する。宣言サイズが 0 または絶対上限 (512 MiB) を超えるアセットは確認時点で拒否する。ダウンロード中に宣言サイズを超えた応答は途中で打ち切り、不完全なファイルは削除する。digest が無いリリースやハッシュ / サイズ不一致は更新対象外 (適用しない)。CPU アーキテクチャが一致しないアセットへはフォールバックしない。

**ダウンロード認証:** gh-release-bridge が保護するタグ範囲のアセット DL には、ビルド時環境変数 `CLIP_REFINER_KEY` で埋め込んだ共有キーを `Authorization: Bearer` で送る。version API による更新確認はキー不要。キー不一致や未埋め込みで保護範囲を取得できない場合は認証エラーになる (利用者向けにキー設定は不要。リリースビルドで埋め込む)。

更新確認・適用は同時に 1 本だけ実行できる。進行中に再実行すると「すでに実行中」と案内する。利用者向けの概要は [README.md のアプリの更新](README.md#アプリの更新) も参照。

## ログイン時の自動起動

設定ウィンドウ「一般」タブから切り替える。現在のユーザー向けレジストリ `Run` キーに登録し、`config.toml` には保存しない。

実行ファイルのパスが変わった場合 (再インストールや移動後など) は、一度オフにしてから再度オンにすると正しいパスで再登録される。ポータブルを USB で持ち歩く用途では、差し替えのたびにパスが変わりやすいため自動起動は向かない ([ポータブルモード](#ポータブルモード) 参照)。

## ログ

ログファイルは設定ディレクトリ内の `logs/` フォルダに日次ローテーションで保存されます。ファイル名の日付 (`clip-refiner.log.YYYY-MM-DD`) はローカルタイムゾーン基準です。不具合報告時は該当する日付のログファイルを添付してください。

| 利用形態 | パス |
| :------- | :--- |
| **通常** (既定) | `%APPDATA%\ClipRefiner\logs\` |
| **ポータブル** | `<実行ファイルのフォルダ>\data\logs\` |

ログレベルの詳細設定 (`RUST_LOG` など) と開発用の環境変数は [DEVELOPMENT.md の環境変数節](DEVELOPMENT.md#環境変数) を参照してください。

## トラブルシューティング

| 症状 | 対処 |
| :--- | :--- |
| 起動時に設定の解析エラーが出る | `config.toml.bak` を開いて通知・ログに示された TOML 構文を修正し、アプリ終了後に `config.toml` として戻す |
| 未知キーの警告が出る | [設定項目](#設定項目) と照合し、タイプミスや廃止済みキーを削除する。既知の設定は引き続き適用される。旧キー (`notify_mode` / `paste_queue` など) は警告対象外 |
| 外部編集が反映されない | 保存後 2 秒ほど待つ。構文エラー通知と当日ログを確認する。設定ウィンドウ表示中はバナーでも知らせる |
| ホットキーが既定値へ戻る | [対応するキー形式](#ホットキー形式)か、他の割り当てと重複していないか確認する。設定ウィンドウから保存した場合は補正内容がフィードバック表示される |
| OCR が `Alt+Shift+O` のまま / 効かない | 既定は `Alt+Shift+G`。既存の `hotkeys.ocr` が残っている場合は設定ウィンドウ「ショートカット」または `config.toml` で変更する |
| 連続記録で `Ctrl+V` してもキューが減らない | 貼り付け取り出しは `Alt+Shift+X` (`hotkeys.continuous_record_paste`)。通常の `Ctrl+V` は OS に任せる |
| Event 監視でも反応が遅い | リスナ初期化失敗時は短周期 peek にフォールバックする。当日ログで `AddClipboardFormatListener` 関連の警告を確認する |
| ワンショットが常駐に委譲されない | 常駐未起動・パイプ接続失敗時はローカル実行になる。[ワンショット IPC](#ワンショット-ipc) と [信頼境界](#信頼境界-同一ユーザー前提) を確認する |
| 大きなテキストや画像を処理できない | [処理の制限](#処理の制限)のサイズ・件数上限を確認する |
| 設定や登録クリップを保存できない | 設定ディレクトリ (通常は `%APPDATA%\ClipRefiner`、ポータブル時は `data\`) の書き込み権限、空き容量、セキュリティソフトのブロックを確認する |
| ポータブルなのに `%APPDATA%` を見ている | 実行ファイルと同じフォルダにファイル名ちょうど `portable` があるか確認する。`CLIP_REFINER_CONFIG_DIR` が優先されていないかも確認する |
| 設定・セレクターが開かない | WebView2 Runtime 未導入の可能性。起動時通知や表示失敗時の導入ページ案内に従い Evergreen Runtime を入れ、アプリを再起動する。手動導入は [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) |
| アイドル時のメモリ使用量が増える | セレクターは既定 `Keep` で非表示後も `WebView` を保持する。[セレクター WebView の保持](#セレクター-webview-の保持-selector_webview_retention) で `DisposeOnHide` / `DisposeAfterIdle` に切り替える |
| 更新確認が失敗する / 適用できない | ネットワークと当日ログを確認する。digest 欠落・SHA-256 / サイズ不一致・アーキテクチャ不一致のアセットは適用しない。認証に失敗した場合はキー埋め込みのない旧ビルドから保護範囲へ更新しようとしている可能性がある。[アプリの更新](#アプリの更新) を参照 |
| ポータブル更新後も古い版のまま | 差し替えヘルパー起動失敗時は展開先がエクスプローラーで開く。実行フォルダへ手動で上書きし、`portable` と `data\` を残したまま新しい `ClipRefiner.exe` を起動する |
